# Course-work knowledge for Morrow

Read through SSH on 6 September 2026 at 00:25 UTC. Host: `meridian`. User: `deploy`. This research read documentation only. It did not call a provider, read credentials, or change ExamplePlatform.

## Applied to Morrow

Preserve course-local design by default. Read the exact target and relevant examples. Make the smallest suitable change. Keep unrelated HTML, media, links, assessment intent, and native settings. A redesign needs a clear request. Apply this rule separately to every course in a batch.

The MCP startup instructions now state this default. The course-audit resource explains how to identify course patterns, separate observed evidence from inference, preserve embedded tools, and verify the saved result. The Morrow brand guide also distinguishes Morrow's interface design from the design of courses it edits.

Course review must check the learner's route: placement, destination names, source references, action steps, and submission instructions. Partial reads must be reported as samples. A course connection does not prove publisher entitlement or a working learner launch.

## Principles retained in existing contracts

- Exact identity, site, course, target, and current source evidence bind each action.
- Catalog discovery describes capability. It does not grant consent.
- Concurrent callers use current preconditions and a single recorded effect. Uncertain writes must not be repeated automatically.
- File verification must eventually compare saved bytes. A filename or success response cannot prove file content.
- Visual work needs saved-state readback and rendered inspection. Limited automated accessibility signals do not establish conformance.

These are reusable principles. ExamplePlatform's daemon layout, descriptor issuer, tool names, production paths, and publisher adapters are specific to ExamplePlatform. They were not copied into Morrow. This research does not clear Connect or MindTap for inclusion.
