# Editor-hosted form transport: brief design (DRAFT, pending live proof)

Date: 2026-09-20
Status: DRAFT. Applies only if the live proof (browser task 6fb3a103)
confirms a top-level form POST from a public HTML editor carries the
Canvas session.

## Why
- Page-context JavaScript is unavailable in managed browser tasks
  (definitive negative gate, 2026-09-20). The fetch lane cannot run live.
- file:// crashes automation, data: top-frame navigation is blocked,
  loopback is a different machine, and Morrow-operated hosting is
  forbidden. The only remaining page that can host an API form is a
  public HTML editor the agent pastes into (proven injection primitive:
  data-URL diagnostic, 2026-09-20).
- The submission mechanism is the one already proven live: cross-site
  top-level form POST to the Canvas API with the session cookies and a
  harvested authenticity_token (retired helper page, assignment 4045370,
  2026-09-20).

## What ships in the brief (packed with the connector)
For every FORM op, the brief carries the COMPLETE form HTML:
- method="POST", action=<absolute https API URL>, target="_top"
- hidden inputs for every field (form-encoded; booleans as true/false)
- hidden authenticity_token (Canvas) / sesskey (Moodle), value rendered
  as the literal placeholder HARVESTED_CSRF_TOKEN with an instruction to
  substitute the token harvested in Step 2
- hidden _method=PUT|DELETE for PUT/DELETE ops (Rails override)
- a submit button
The agent pastes, runs, and clicks Submit. No agent-authored HTML.

## Editor chain (brief text)
Primary: https://www.w3schools.com/html/tryit.asp?filename=tryhtml_form_submit
Fallbacks (in order):
  1. https://www.tutorialspoint.com/online_html_editor.php
  2. https://jsfiddle.net/ (HTML pane, Run)
The brief tells the agent: if the primary editor fails to load or run,
move to the next; report which editor was used per op.

## Brief flow
1. Session check (unchanged): GET /api/v1/users/self, verify principal.
2. CSRF harvest (unchanged): read csrf-token/sesskey from page HTML,
   never report the value.
3. Per FORM op: goto editor, select-all + paste the op's HTML
   (substituting HARVESTED_CSRF_TOKEN), Run/Preview, click Submit in the
   result, read the JSON the tab navigates to.
   GET ops: plain navigation (unchanged).
4. Report format (unchanged): op_id | http_status | body, then RESULTS_JSON.
