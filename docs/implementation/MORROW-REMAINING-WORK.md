## Scope and evidence rules

Morrow is not complete because a catalog contains routes or a local test passes. A function moves forward only when its exact signed-in target, human control, one explicit Morrow dispatch, saved-result check, and recovery state are established. A live result for one disposable target is evidence for that result only.

The requested scope stays broad. It includes the full Canvas accessibility and repair program; all Moodle core modules, question types, cross-cutting functions, and administration; an official Blackboard REST API integration; work across dozens of courses and concurrent assistants; two-install shipping on supported systems; publisher rights; and accurate phone and website evidence. It is not limited to common educator tasks.

| Evidence label | Meaning |
| --- | --- |
| **Verified path** | A reviewed operation reached a fresh saved-state check on its stated target. |
| **Source or fixture only** | Code and local checks exist. This does not prove a customer, role, browser, or provider result. |
| **Live-unverified** | A workflow or route is implemented but lacks the required signed-in result check, wider role proof, or independent review. |
| **Blocked or unavailable** | A needed connection, byte-level read, authority, contract, or legal permission is absent. |

## Which gate covers what

`pnpm check` runs `pnpm test`: the workspace build, every package test, `node --test scripts/test/*.test.mjs`, and the desktop installer suites. That glob takes test files only, so four harnesses stay outside it, and a passing `pnpm check` is not a browser result.

`pnpm test:browser` (`scripts/run-browser-harnesses.mjs`) is the named gate for them. It runs `scripts/test/canvas-connector-browser.mjs` and `scripts/test/bridge-maintenance-cft.mjs` in Chromium, each under its own timeout, and writes `output/browser-harness/receipt.json` with one recorded result for every harness. `pnpm test:browser:attended` adds `scripts/test/canvas-file-optional-permission-proof.mjs`, which needs a person to answer Chrome's own permission prompts. `scripts/test/desktop-windows-smoke.mjs` is native Windows only, runs in the `windows-2022` job of `.github/workflows/desktop-release.yml` on manual dispatch, and is recorded in the receipt as not run on this host rather than as passed.

`.github/workflows/ci.yml` runs `pnpm check` and the desktop suites only. The browser gate needs the Playwright Chromium build, which nothing in this repository installs, so it runs on a host that already has it.

Release staging reads that receipt: a candidate is not promotable while a harness is unrecorded, recorded against another commit or a changed working tree, or recorded as anything other than passed. `pnpm weekend:check` reports the same state as `browser_harness_receipt`.

## 1. Program-wide Canvas accessibility audit and repair

This is the highest-value product gap. The current [`morrow_audit_course`](../../packages/mcp-server/src/course-audit.ts) tool reads **one exact item**. It detects a fixed set of saved-source signals, each returned as its own list that needs human review. It makes no conformance decision. A no-signal result is not an accessibility pass.

Current protected missing-image-alt repairs cover a non-block-editor Page, an Assignment description, a Discussion message, a Classic Quiz description, a Classic Quiz question, and supported direct/nested New Quiz QuestionItem fields. They reread the exact item and preserve protected content and settings. The Classic Quiz description path sends only `quiz[description]`, verifies the full protected Quiz state, and reruns the selected image-alt check. The Classic Quiz question path is different, because Canvas rebuilds a question from the whole request: it resends every field the fresh read returned, refuses a question in a question group, an unsupported question type, an incomplete read, and a read carrying state it cannot send back, then compares the whole saved question except the one edited field. No live Canvas tenant has proved that round trip, so it stays live-unverified behind its own Edit category. The Stimulus source contract remains incomplete. Existing Item Bank writes are held, except one guarded repair that adds alternative text to a single bank question after every course the bank reaches is listed and confirmed. `morrow_plan_item_bank_question_image_alt_repair` produces that call. It reads the course, the bank entry and the question fresh, refuses a stale question, an incomplete fan-out record and an acknowledgement that is not exactly the courses the bank reaches, and names every one of those courses before it describes the change. No Item Banks frame has been read on a live Canvas tenant, so this path is unproven end to end, and every plan it produces still asks a person to approve it. Canvas file reading retrieves confirmed text/HTML bytes after explicit Chrome permission and local opt-in. Native Chrome grant, denial and removal passed on synthetic hosts, including cross-origin cookie confinement and learner-name replacement. The [receipt](../../output/canvas-file-permission-2026-09-06/native-permission-final-receipt.json) records the tested source; the final archive still needs its own proof. PDF, Office and other binary content does not receive an accessibility pass.

Complete this as a program-level workflow, not as a sample audit:

1. Inventory every readable item in each selected course and record what could not be read.
2. Audit Pages, assignment descriptions, Discussions, Classic Quiz descriptions and questions, New Quiz instructions and items, Item Bank entries, Files, linked documents, media, and learner-facing navigation. Keep item, field, digest, criterion, learner effect, and evidence together.
3. Add repair contracts by surface. Each must preserve unrelated content and settings, require human review or valid bounded Morrow authority, dispatch once, reread the saved target, and rerun the audit.
4. Inspect saved rendering in native learner-facing desktop and narrow layouts. Perform and record the checks that source parsing cannot establish: keyboard path, focus order, link purpose, color and contrast, tables, equations, captions, transcripts, audio description, player controls, and interaction behavior.
5. Read actual file bytes and native file metadata before making file, PDF, Office-document, image, or media accessibility claims. Missing bytes, inaccessible content, or an unsupported viewer stays blocked, not passed.

Observable completion is a per-program audit ledger. It has one final state for every discovered target: repaired and verified, manually checked, not applicable with evidence, unread, blocked, or held. It must never turn incomplete reads or manual work into a passed course claim.

The read-only [`morrow_program_ledger`](../../packages/mcp-server/src/program-ledger.ts) tool now derives that ledger. It takes a saved `morrow.course-inventory.v1` report, the audit results for that inventory's audit children, and any repair operation records, and it states one final state for every discovered target: the six states above plus `evidence_ready_pending_review` for evidence a person must still review. A target Morrow could not read at all, including one an incomplete source list never returned, is unread with its coverage-gap code. A Canvas record Morrow did read stays auditable even when the rest of its list is still unread, so a course longer than one bounded read still produces audit children. An audit that errored, a file Morrow could not read, and a repair whose operation is `applied_or_unknown` are blocked. A read with no source signal is pending review, never a pass. The ledger refuses a refused course and a child set that disagrees on target identity, fixes `conformance_claim` to `none`, and carries the unread and truncated source-list counts with the residual manual-review categories. It reads no course: every state comes from local records, so the ledger stays live-unverified. Steps 2 through 5 above are still incomplete, and the ledger reports that incompleteness rather than hiding it.
